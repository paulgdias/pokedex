# Components Guide

Data/filter/sort logic lives in `src/utils/` (see `utils-guide.md`). Components mostly render and wire it up.

## Styling details

- Tailwind utilities inline; `twMerge` so callers can override via `className`.
- Shared class strings live in `src/styles/Pokedex.ts`.
- Use `Panel` (card surface), `SectionLabel` (small uppercase heading), and `PageHeader` (page top block) instead of repeating their classes.
- Design tokens (defined in `src/styles/index.css` `@theme`): `paper`, `surface`, `sand`, `track`, `chip`, `chip-hover`, `wash`, `ink`, `muted`, `subtle`, `line`, `line-strong`, `accent`, `accent-strong`, `sidebar-*`, and one colour per Pokémon type (`bg-fire`, etc.). Fonts: `font-display`, `font-sans`, `font-mono`.
- `typeColors` in `@customTypes/PokemonTypes` maps type name → `bg-*` class and is the source of `POKEMON_TYPES`. Adding a type colour requires both the map entry and the `@theme` token.
- **Focus**: the global `:focus-visible` outline (accent) is drawn outside the element, so inside scroll containers it may be clipped. Nav rows use `focus-visible:-outline-offset-2`; cards draw a 2px `::after` border instead (see `cardClass`).
- `.pokedex-scroll` styles scrollbars for the virtualized grid and overflow containers.

## Loading, empty, and error states

- **Route loading**: `LoadingSpinner` via `HydrateFallback` on first load. On client-side navigation, `Layout` overlays it on `<main>` after a 200ms fade-in delay (only when the pathname changes, so cached navigations don't flash it).
- **Empty results**: inline `EmptyState` in `src/pages/Pokedex.tsx`.
- **Errors**: `ErrorBoundary` in `Layout` (around the outlet) and around the list in `Pokedex`. Toasts via Sonner.

## Adding a component

1. Create `Name/index.tsx` (default export, Tailwind + `twMerge`), `Name/Name.test.tsx` (behaviour, callbacks, edge cases), `Name/Name.stories.tsx` (at least one story with a `play` function that calls `expect`; also gets the axe check), and `Name/Name.mdx` (`<Meta of={Stories} />`, short description, props via `<ArgTypes of={Stories} />`, and a `<Canvas>` per story). `structure.test.ts` enforces this.
2. Use React Aria primitives for anything interactive.
3. Keep filtering, sorting, and URL logic in `src/utils/`, not inside the component.
4. Run `npm run verify`.

**MDX note**: Storybook's MDX engine has no GFM, so `| pipe |` tables render as plain text. Use an HTML `<table>` for props when the type lives in `src/types/` (as with `PokemonCard`).
